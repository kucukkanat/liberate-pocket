LOCAL DEVICE TOOL / EXPERIMENTAL

Pocket Explorer.

Inspect your recorder's GATT services, read accessible characteristics, list recordings and download MP3s when the recorder's command service is available. No backend or cloud.

00 — Get your session key

Every Pocket only accepts commands after it receives its 16-character session key. Pairing in Chrome or in macOS Bluetooth settings does not give you this key. Pick one way to get it:

After a hardware reset the Pocket binds to the first key it receives. This app sends it a random key of yours. The vendor app then can't connect until you reset again and pair it there.

Copy off any recordings you need first: whether a reset keeps them is unconfirmed.

  1. Free the Pocket

    Close the vendor app or turn off your phone's Bluetooth. The Pocket accepts one connection at a time.

  2. Triple-click the side button

    The LED starts blinking red.

  3. Press and hold the side button

    Keep holding until the red blinking stops, then release.

  4. LED pulses blue

    The reset worked and the Pocket is waiting for a new key.

  5. Claim it here

    Click Find Pocket, then Claim reset Pocket. Save the key it shows.

  6. Reconnect

    The Pocket drops the link right after pairing. Click Find Pocket again; recordings load automatically.

“Claim refused” means the key wasn't cleared. A softer reset exists that keeps the old key, so repeat steps 2–4 until the LED pulses blue.

The Android vendor app logs an analytics field distinct_id. It is a 28-character account ID; its first 16 characters are the session key.

  1. Developer options

    Settings → About phone → tap Build number 7 times.

  2. USB debugging

    Settings → Developer options → enable USB debugging. Connect the phone by cable and allow the computer.

  3. Install adb

    Android SDK Platform-Tools, or brew install android-platform-tools.

  4. Watch the log

    Run adb logcat | grep -i distinct_id, then open the vendor app and let it connect to the Pocket.

  5. Take the first 16"distinct_id":"K7Q2M9XR4T1BZ8WAC3PL5NDV"

    Example only. Paste the highlighted part into the key field.

Record the Bluetooth traffic while the vendor app connects and read the key it writes.

  1. Enable full HCI log

    Developer options → Enable Bluetooth HCI snoop log → Full. The default “filtered” mode truncates packets so the key is unreadable.

  2. Restart Bluetooth

    Toggle Bluetooth off and on so the setting takes effect.

  3. Connect with the vendor app

    Open it and let it connect to the Pocket.

  4. Pull the log

    adb bugreport bug.zip, then find btsnoop_hci.log inside (path varies by phone, often FS/data/misc/bluetooth/logs/).

  5. Open in Wireshark

    Filter: frame contains "APP&SK&"

  6. Read the valueValue: APP&SK&K7Q2M9XR4T1BZ8WA

    The 16 characters after APP&SK& are the key.

Apple's PacketLogger can capture an iPhone's Bluetooth traffic from a Mac.

  1. Get PacketLogger

    Download Additional Tools for Xcode from developer.apple.com; PacketLogger is in the Hardware folder.

  2. Install the Bluetooth profile

    On the iPhone, install Apple's Bluetooth logging profile from Profiles and Logs, then restart the phone.

  3. Start an iOS trace

    Connect the iPhone by cable. In PacketLogger: File → New iOS Trace.

  4. Connect with the vendor app

    Open it and let it connect to the Pocket.

  5. Search the trace

    Search for APP&SK&; the next 16 characters are the key.

    ATT Write … APP&SK&K7Q2M9XR4T1BZ8WA

The key belongs to your vendor account, not the device. A key captured once (B, C or D) works for every Pocket on that account, and a key you claimed with (A) is stored in this browser when “Remember key” is on. It changes if you sign in to the vendor app as someone else.

Treat the key as a secret. Its first 8 characters are also the Pocket's Wi-Fi password.
